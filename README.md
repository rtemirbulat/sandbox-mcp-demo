# Sandbox MCP Demo

Минимальный статический фронтенд для проверки цепочки Claude Code → LiteLLM → Sandbox MCP → Coolify.

В корне находится `index.html`. Нет зависимостей, шага сборки, серверного кода, базы данных или секретов. Ожидаемый тип в MCP: `static`.

## Проверить локально

Откройте `index.html` в браузере. Либо выполните из папки репозитория:

```bash
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080.

## Опубликовать через MCP

После подключения Sandbox MCP в Claude Code отправьте:

> Через Sandbox MCP оцени https://github.com/rtemirbulat/sandbox-mcp-demo из ветки main. Название приложения — sandbox-mcp-demo. Назначение — проверка публикации статического фронтенда. Класс данных — none. Если decision=allowed, разверни commit_sha из оценки в TEST с новым idempotency_key. Проверяй status до завершения и верни URL и результаты проверок.

Успешный тест: `state=succeeded`, Gitleaks и Trivy пройдены, smoke возвращает HTTP 200; по URL открывается страница «Тестовый фронтенд открыт» с отметкой `v1`.

Поле `data_classes` передаётся как `["none"]`. Для первой оценки используйте `git_ref="main"`; для выпуска — полный commit SHA из ответа оценки.

## Проверить обновление

1. Поменяйте отметку `v1` в `index.html` на `v2` и отправьте новый commit в GitHub.
2. Вызовите `validate_and_deploy` для прежнего `app_id`, нового полного SHA и нового `idempotency_key`.
3. Дождитесь `succeeded` через `status`; откройте тот же URL и проверьте отметку `v2`.

Страница сама не знает состояния деплоя и не выполняет проверки: их результат возвращает MCP. Пилот публикует сайт без SSO. Фактическая доступность зависит от работы тестовых VM; срок жизни смотрите в `expires_at` ответа `status`.
